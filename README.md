## Problem Statement

The Indian coal mining sector's governance activities (statutory compliance,
inspections, safety observations, production reporting, environmental
monitoring, contract management) are fragmented across manual documentation
and spreadsheets, causing data inconsistency, delayed decisions, and weak
field-level monitoring. Full statement: see the original SIH26024 brief.

## Solution Summary

A centralized AI-enabled governance platform for coal mining operations — designed with zero physical hardware requirements. The platform integrates **Google's Gemini API** for intelligent inspection draft analysis, conversational voice queries, and multilingual translation (requires a `GEMINI_API_KEY` configured in `.env`). Operational data is generated by a synthetic simulator so the platform can demonstrate real-time behaviour and dynamic risk assessment during evaluation.

## What's Implemented (Phases 1–6)

- ✅ **Authentication & Role-Based Access Control (RBAC):** JWT authentication (`login`, `logout`, `me`), bcrypt password hashing, and server-side RBAC middleware enforcing permissions across 6 distinct roles (`SUPER_ADMIN`, `MINE_MANAGER`, `SAFETY_OFFICER`, `INSPECTOR`, `CORPORATE_MANAGER`, `REGULATORY_OFFICER`).
- ✅ **Mine Management:** Full CRUD operations for coal mines with subsidiary associations, geo-coordinates (latitude/longitude), production capacity, status management, and interactive Leaflet GIS map visualization.
- ✅ **Compliance Rules Engine:** Configurable compliance rules categorization, severity levels, penalty tracking, statutory references, and rule browsing/management with role-based write permissions.
- ✅ **Inspections & Audits:** End-to-end inspection scheduling, real-time draft observations, photo/document attachments, status workflows (Scheduled, In Progress, Completed, Follow-up Required), and automated violation triggers.
- ✅ **Violations & Escalations:** Automatic violation logging from failed inspections or threshold breaches, severity classification (Low, Medium, High, Critical), penalty computation, and deadline tracking.
- ✅ **Corrective Actions (CAPA):** Corrective & Preventive Action assignment, remediation submission, multi-tier verification workflows, and automated escalation checks for overdue actions.
- ✅ **Incidents & Emergency Management:** Safety incident reporting, root cause tracking, severity levels, and instant one-click emergency broadcast triggers.
- ✅ **Contractor Compliance:** Contractor tracking, worker onboarding, safety ratings, compliance scoring, automatic contract expiry warnings, and blacklist enforcement.
- ✅ **Environmental & Production Logging:** Real-time tracking of environmental metrics (PM2.5, PM10, SO2, NO2, noise, water pH) and production metrics (daily output, overburden removal, equipment uptime).
- ✅ **Attendance & Worker Roster:** Shift-based workforce attendance logging, worker qualification records, and attendance reporting.
- ✅ **Grievance Redressal:** Worker and community grievance registration, category tagging, officer assignment, resolution tracking, and escalation management.
- ✅ **Documents & OCR Parsing:** Document repository supporting upload of safety certificates, environmental clearances, and DGMS notices with automated Tesseract OCR text extraction.
- ✅ **Notification System:** Real-time and persistent in-app notifications for critical alerts, overdue corrective actions, threshold breaches, and emergency broadcasts.
- ✅ **Automated Reports:** Instant generation and export of PDF and CSV compliance summary reports, inspection audits, and monthly risk retrospectives.
- ✅ **AI Risk Scoring & Anomaly Detection:** Python-based explainable risk scoring engine calculating multi-factor mine risk indexes (0–100) alongside scikit-learn anomaly detection for operational and environmental metrics.
- ✅ **Gemini-Based Inspection Analysis:** Google Gemini AI integration that analyzes draft inspection observations in real time to suggest severity ratings, matching statutory compliance rules, root causes, and recommended corrective actions.
- ✅ **Multilingual Voice & Translation Assistant:** Gemini-powered speech-to-text / voice query assistant providing hands-free operational insights and instant multilingual translation of inspection notes (Hindi, Bengali, Odia, etc.).
- ✅ **Tamper-Evident Audit Logging:** Comprehensive audit logging on all security events, data mutations, and administrative actions with cryptographic SHA-256 hash-chain verification.
- ✅ **Operational Data Simulator:** Standalone dynamic simulator simulating multi-mine operational data streams across standard, high-risk, and emergency simulation modes with real-time UI control.
- ✅ **Docker Compose Setup:** Fully containerized multi-container orchestration for MySQL 8+, Go backend, Python AI service, and static frontend via Nginx.

## Installation & Setup

> [!WARNING]
> **CRITICAL SECURITY NOTICE:**  
> **`.env` and `.env.example` files must NEVER contain real production secrets, private passwords, or active API keys.** If any API key (such as `GEMINI_API_KEY`), database password, or JWT secret has been accidentally committed or exposed, **rotate and invalidate it immediately** before pushing code to a public repository. Always keep your local `.env` file gitignored.

### 1. Clone and configure environment

```bash
git clone <your-repo-url> coal-governance
cd coal-governance
cp .env.example backend/.env
# edit backend/.env — set DB_PASSWORD, JWT_SECRET, and GEMINI_API_KEY
```

### 2. MySQL setup

```bash
mysql -u root -p < database/schema.sql
mysql -u root -p < database/seed.sql
```

This creates the `coal_governance` database, all 25 tables, and seeds demo
users, subsidiaries, mines, and compliance rules.

### 3. Go backend setup

```bash
cd backend
go mod tidy
go run main.go
```

When running the app with Docker Compose, the backend is exposed on
`http://localhost:8081` and the frontend is served on `http://localhost:8000`.
Verify with:

```bash
curl http://localhost:8081/api/health
```

### 4. Frontend setup

The frontend is static HTML/CSS/JS — no build step required. Serve it with
any static file server, e.g.:

```bash
cd frontend
python -m http.server 8000
```

Then open `http://localhost:8000/login.html`. If your backend runs on a
different host/port, edit `frontend/js/config.js` (`API_BASE_URL`).

### 5. Python AI service

```bash
cd ai-service
pip install -r requirements.txt
python app.py
```

Starts the Flask AI service on `http://localhost:5000` handling risk scoring, anomaly detection, OCR processing, and Gemini AI endpoints.

### 6. Simulator

```bash
cd simulator
python mine_data_generator.py
```

Generates live operational, environmental, and compliance telemetry for active mines, supporting configurable normal, high-risk, and emergency simulation modes.

### 7. Docker Compose (alternative to steps 2–6)

```bash
cp .env.example .env   # docker-compose reads DB_PASSWORD / JWT_SECRET / GEMINI_API_KEY from here
docker compose up --build
```

- Backend: `http://localhost:8081`
- Frontend: `http://localhost:8000`
- AI service: `http://localhost:5000`
- PostgreSQL: `localhost:5433`

## Security Notes

- **CORS Configuration:** CORS is currently configured for local hackathon development and testing (`*`). For staging or production deployments, restrict `AllowOrigins` in [`backend/main.go`](backend/main.go) to trusted frontend origins only.
- **Password Security:** Passwords are bcrypt-hashed; plaintext passwords are never stored.
- **Environment Variables & Secrets:** JWT secrets, database credentials, and `GEMINI_API_KEY` are read strictly from environment variables. Real secrets must never be committed to source control.
- **Server-Side RBAC:** RBAC is enforced strictly on the server side via Gin middleware on every mutating route, independent of UI controls.
- **Tamper-Evident Audit Trail:** All governance actions, authentication events, and data mutations are cryptographically logged to `audit_logs` with SHA-256 hash chaining for transparent verification.
